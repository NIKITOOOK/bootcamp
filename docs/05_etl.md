PostgreSQL (`dota`) и MongoDB (`dota_events`) → **RAW** (копия источников, платформа) → **STAGE** (очистка, соединения, свёртка, наши потоки) → **MART** (витрины под гипотезы) → Trino → Superset. История матчей живёт только в RAW, источники чистятся каждые 4 часа. Хранилище: Iceberg на S3, REST-каталог. Оркестрация: Airflow, DAG генерируется Порталом из SQL и запускается по обновлению входных таблиц (datasets). Вычисления: Spark 4.1.2. Lineage: события уходят в Marquez.

Схема: `Источники → RAW (raw.pg__*, raw.mongo__*) → STAGE (4) → MART (3) → Superset`.

## Правила очистки STAGE (реализованы в SQL)

- **Дедупликация.** `row_number() over (partition by <ключ> order by sys_insert_stamp desc, job_id desc) = 1`: RAW дописывает строки при каждой загрузке, берём самую свежую версию.
- **Режим.** Исключаем Turbo (`game_mode <> 23`).
- **Полнота.** Матчи от 15 минут (`duration >= 900`), `human_players = 10`, ровно 10 игроков и 10 разных героев с `hero_id > 0`.
- **Анонимные аккаунты.** `account_id = 4294967295` не используем для соединений с покупками, золотом и изучением способностей; ставим флаг `is_anonymous`. Командное золото считаем только если анонимов в команде нет.
- **Позиция.** `pos_proxy` — место по `net_worth` в команде (в источнике позиции нет).
- **Тип здания.** По диапазону `npc_id`: 16–35 башни (T1–T4), 38–49 бараки, 50–51 трон.
- **Падения зданий.** Из битовых масок `tower_death_events`: новый бит относительно предыдущего события.
- **Тип источника урона.** Способность, предмет, призыв, юнит от Helm, обычная атака героя.
- **Окна времени.** 0–10, 10–15, 15–30, 30+ минут; в MART добавляется фаза матча 0–15, 15–30, 30+ (planned).

## Режим записи и инкремент

- Режим SQL в Портале — `CREATE OR REPLACE`: **полная пересборка** таблицы при каждом запуске. Это принятый вариант для текущей версии (**готово**).
- Инкрементальная загрузка по новым `match_id` реализована отдельными Spark-скриптами (`sql_portal/incremental_spark_script/`: matches, players, building_falls, tower_hits, team_early_push). Они **написаны, но не запущены** на платформе (planned). Вопрос к организаторам: можно ли подключить скрипт как поток.
- Iceberg хранит 5 последних snapshot, откат дальше невозможен.

## Как повторить

1. Портал → Разработка → новый поток, слой STAGE или MART, имя `t1_c13_<объект>`.
2. Вставить SQL из `sql_portal/portal_prod/` (для `tower_hits` версию из `portal_prod_v2/`).
3. «Показать данные» (предпросмотр идёт через Trino), затем проверка разработки; форму после проверки не менять.
4. «Создать и запустить»; смотреть статус в Airflow (Grid, Logs) и в Spark History.
5. Поток нельзя править, только удалить и создать заново; удалять можно, только если от него никто не зависит.
